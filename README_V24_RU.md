# Corporation v24 — Premium Market Update

Основа: Corporation_v23_ALPHA_AUDIT_FIX.zip. Полный архив файлов этой версии, не патч к отдельным строкам. Живой сервер не изменялся.

## Установка без сброса прогресса

1. Создай резервную копию SQLite через админ-панель и скачай её. Не удаляй Railway Volume.
2. Распакуй архив поверх файлов локального репозитория corporation-game. Не удаляй остальные файлы репозитория. В архиве нет базы, токенов, .env или чужого прогресса.
3. Backend Railway: подключён существующий Volume; BOT_TOKEN и WEBAPP_URL остаются прежними. ADMIN_IDS — только разрешённые тобой числовые Telegram ID через запятую, без @username. Пустой ADMIN_IDS запрещает доступ всем. Проверь эту переменную на ОБОИХ сервисах. ALLOW_DEV_AUTH=0, APP_ENV=production. DB_PATH оставь прежним: сервер использует файл с этим именем на Volume.
4. Backend Start Command: `uvicorn app:api --host 0.0.0.0 --port $PORT --workers 1`. Bot Start Command: `python bot.py`. Оба сервиса устанавливают requirements.txt. Python 3.11+.
5. Выполни из папки локального репозитория:

```bash
git status
git add app.py bot.py market_v24.py security_v24.py web tests requirements.txt Procfile .env.example README_V24_RU.md QA_V24_RU.md ASSETS.md
git commit -m "Release v24: premium UI, market patterns and security fixes"
git push origin main
```

6. Дождись успешного запуска обоих сервисов. Открой игру заново через кнопку бота. Существующие активы сохраняются; новые таблицы и три акции добавляются автоматически. Не нажимай «Новый сезон»/«Сброс», если хочешь сохранить прогресс.

## Изменения

- Все 11 подтверждённых наблюдений объединённого QA: UX-001…008, UX-010…012. UX-009 не является принятым дефектом отчёта. Подробности проверок в QA_V24_RU.md.
- Тёмный графитовый интерфейс с приглушённым золотом, единые карточки, кнопки, типографика, мягкие переходы и поддержка reduced-motion.
- Шесть нижних кнопок в одной строке. Короткие названия: Бизнес, Биржа, Объекты, Налоги, Капитал, Рейтинг. Полные названия сохранены в aria-label.
- VIP-дома с локальными фотографиями современной дорогой недвижимости, иллюстрирующими класс объекта. Цены и ID недвижимости не изменены.
- Полноэкранный режим через Telegram requestFullscreen (Bot API 8.0+); учтены безопасные области. На клиентах без поддержки остаётся expand. Документация: https://core.telegram.org/bots/webapps
- Каждая новая публикация через 60 минут + случайные 0…45 минут от предыдущей. Расписание хранится в SQLite, переживает перезапуск и не выдаётся в публичный API. Двухминутная реакция на опубликованную новость сохранена.
- Свечи OHLC сгруппированы по реальным пятиминутным интервалам серверной игровой истории. Нет случайных теней или фальшивой линии. Старые свечи неизменны при приходе новых точек. До 720 точек на КАЖДУЮ акцию.
- Один розыгрыш с вероятностью 5% каждый час на весь рынок. Выбирается одна акция с запасом до границ; паттерн занимает 35–40 минут, затем рост 25–40% от уровня пробоя с учётом потолка. Паттерны: перевёрнутая «голова и плечи» (бычий вариант) и восходящий треугольник. Это реальные будущие игровые котировки, по ним исполняются сделки; прошлая история не переписывается. Новостной шок прерывает текущую фигуру. Если подходящих акций нет, событие пропускается. При долгом простое восстанавливается максимум 12 часов рынка, без бесконечного накопления новостей.
- В рейтинг включены все игроки; вход прокручивает к своей компании, доступны кнопки вверх и обратно. Названия безопасно экранированы.

## Безопасность

HMAC-подпись Telegram, срок действия initData, строгий серверный ADMIN_IDS, центральная и маршрутная проверки прав, лимиты запросов по проверенной личности и соединению, ограничение тела даже без Content-Length, строгие целые количества, сверка цены, транзакции SQLite, защита от повторной продажи бизнеса при параллельных запросах, экранирование пользовательского HTML, закрытые OpenAPI/docs. Telegram username не выдаётся в обычном рейтинге/профиле. Локальная отладка возможна только при одновременных APP_ENV=test и ALLOW_DEV_AUTH=1, вне Railway.

Ни один код не гарантирует абсолютную неуязвимость или защиту от любого DDoS. Доступ к Railway/GitHub/BotFather остаётся отдельной границей безопасности. Если BOT_TOKEN ранее утекал, замени его через BotFather на обоих сервисах; предыдущие initData после замены станут недействительны. Подписанное initData остаётся bearer-доступом до истечения срока (по умолчанию час): после этого нужно заново открыть игру.

После выкладки проверь на своём телефоне fullscreen, фото, сделки, админ-доступ и сохранность активов. Физический Telegram-клиент и твоя рабочая база здесь не использовались.

# Corporation v23 — исправления альфа-аудита

## Установка

Распакуйте содержимое ZIP в `C:\Users\Pentagon\Desktop\corporation_game_MA` с заменой одноимённых файлов. Это готовые файлы приложения: запускать старые APPLY_UPDATE / APPLY_SECURITY_UPDATE не нужно. Остальные файлы проекта и существующий requirements.txt оставьте на месте.

## Исправления

| ID | Изменение |
| --- | --- |
| UX-001 | Денежный остаток в шапке называется «Свободные деньги». Общий капитал в статистике остаётся суммой денег и активов. |
| UX-002 | Улучшения показывают процент от базового дохода, точную прибавку и будущий доход. Предпросмотр рассчитывает сервер по той же аддитивной модели. Например: 420 → 525 ₽/ч, +105 ₽/ч. |
| UX-003 | До подтверждения покупки недвижимости загружаются актуальные баланс и цена; при нехватке показываются нужная и недостающая суммы. Сервер повторно проверяет деньги внутри транзакции. |
| UX-004 | Процент в списке и карточке акции подписан «к предыдущей котировке» — именно последние две записи истории использует сервер. Переключение графика не меняет базу процента. |
| UX-005 | Все подписи нижнего меню — 11 px. На экранах до 600 px меню размещено в два ряда по три раздела; снизу добавлено место под панель. |
| UX-006 | Вся строка количества проверяется целиком. Дроби, текст, ноль, отрицательные и слишком большие значения отклоняются. Сервер принимает только положительный JSON integer в безопасном диапазоне. Правило действует для покупки и продажи акций и облигаций, включая дополнение отчёта о продаже ОФЗ. |
| UX-007 | Нижняя навигация сбрасывает состояние карточки акции; новости доступны после возврата. Обновление данных сохраняет выбранную акцию и режим графика. Запоздавший ответ акции не перерисовывает другой раздел. |
| UX-008 | Отсчёт следующей новости и реакции рынка обновляется каждую секунду по времени события с поправкой на серверные часы. После возврата на вкладку загружается актуальная лента; при достижении нуля запрашивается новое состояние. |

Перед сделкой показываются инструмент, количество, цена и сумма. При изменении котировки сервер отвечает 409 без исполнения по новой цене. Повторное нажатие во время обработки блокируется в интерфейсе. Автоматического повтора POST нет; при сетевом сбое после отправки следует обновить портфель перед новой попыткой.

Дополнительно унифицирован порядок дня и месяца в графике прибыли. Включён слой адаптации статистики к мобильным экранам. Версии статических ресурсов обновлены для обхода старого кэша.

## Основа сборки

Код восстановлен из последних доступных архивов проекта, а не выгружен с Railway:

- Corporation_v18_Investment_Hub_RealEstate — базовый интерфейс;
- Corporation_v21_Market_News_Update — новости, сезоны, админский интерфейс;
- Corporation_v22_1_Statistics_Mobile_Fix — последняя доступная полная версия backend, управление игроками и адаптация статистики;
- Corporation_FINAL_ALPHA_v22, v22_1_REFRESH_BUTTON, v22_2_START_20000_MCDONALDS, v22_4_SELECTED_NEWS_IMAGES_MOBILE — последовательные обновления;
- Corporation_SECURITY_v22 — защита Telegram-авторизации.

Старый установщик безопасности ожидал строго STARTING_MONEY=10000 и завершался ошибкой на версии с 20000. В эту сборку защита внесена уже применённой с сохранением 20000. Политика загрузки ресурсов разрешает используемый игрой Leaflet с unpkg.com. Производственный X-User-Id по-прежнему запрещён; действуют проверка подписи Telegram и ADMIN_IDS.

Если после этих архивов проект менялся вручную или другим разработчиком, эти изменения не могли быть учтены: сравните файлы перед заменой. Отчёт тестера описывает поведение, но не содержит исходный код текущего сервера.

## Выполненная проверка

8 серверных тестов прошли на временной SQLite-базе:

- 44 некорректных значения на четырёх маршрутах торговли, без изменения денег и портфеля;
- покупка/продажа одной бумаги, нехватка бумаг и превышение баланса;
- отклонение неподтверждённой новой цены;
- все 24 порядка покупки улучшений кофейни и пример 420 → 525;
- формула полного капитала;
- покупка недвижимости при балансе ниже цены, равном цене и выше цены;
- сохранение денег и бумаг при повторной инициализации базы;
- отклонение неподписанных запросов без режима разработки.

Интерфейс проверен в jsdom с настоящим локальным API: нижняя навигация, возврат из акции, обновление свечного графика, 36 ошибочных вводов, отмена, максимальное количество, двойное нажатие, проверка денег до подтверждения недвижимости. Для таймера часы были сдвинуты на 50 секунд: отображение пересчиталось по прошедшему времени.

Среда: Python 3.12, FastAPI 0.141.1, Pydantic 2.13.5, Uvicorn 0.53.0, httpx 0.28.1. Существующие зависимости проекта автоматически не изменяются. Тестовые библиотеки не нужны работающему боту.

Ограничения: это не полный нагрузочный или security-аудит. Реальный Telegram WebView, ручной native prompt, физический телефон и визуальная вёрстка в Chrome не проверены: запуск браузерной проверки был недоступен. jsdom проверяет DOM и обработчики, но не реальный размер и расположение элементов. После установки повторите оба ключевых сценария UX-006/007 в Telegram, проверьте нижнее меню на 320/390 px и сохранность прогресса после деплоя. Абсолютное отсутствие других ошибок не гарантируется.

## Повторный запуск тестов

Backend: установите тестовые зависимости fastapi, pydantic, httpx и выполните `python tests/test_audit.py`. Тест создаёт собственную временную базу.

Frontend: установите jsdom для Node.js; запустите отдельный локальный backend с ALLOW_DEV_AUTH=1, портом 8765 и новым тестовым DB_PATH. Выполните `node tests/test_frontend.cjs`. Этот тест покупает/продаёт активы пользователя 999001, поэтому его можно запускать только на отдельной тестовой базе. При нестандартном расположении jsdom задайте CORP_JSDOM. Не включайте ALLOW_DEV_AUTH на рабочем сервере.

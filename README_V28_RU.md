# Corporation v28 — независимые бизнесы и плавный интерфейс

Основа: Corporation_v26_3_NEWS_RANGE_FULL_IMAGE_FIX.zip.

## Изменения

- Верхняя панель с названием и балансом видна только на стартовой вкладке «Бизнес». На Бирже, Объектах, Налогах, Капитале, Рейтинге и в профилях игроков она скрыта.
- В «Бизнесах» два раздела: «Открыть бизнес» и «Мои бизнесы». Можно покупать несколько экземпляров каждого типа по прежней базовой цене.
- Каждый экземпляр имеет отдельную запись: уровень, четыре улучшения либо собственные автомобили, гараж и срок его расширения.
- Карточки бизнесов, экран акции, налоги и карточки недвижимости обновляют DOM на месте. Покупки не пересоздают весь список автопарка. Положение страницы сохраняется до следующей отрисовки. Есть защита от повторных нажатий во время операции.
- Ползунок и ручное поле количества акций синхронизированы. Количество, сумма и предварительный налог при продаже пересчитываются локально. Покупка, продажа, «купить на все» и «продать все» требуют подтверждения. Сервер проверяет ожидаемую цену: при её изменении отклоняет операцию, деньги не списывает.
- Все экземпляры входят в автоматический доход, капитализацию, статистику покупок, публичные профили, рейтинг и административные расчёты.
- Лёгкие анимации, поддержка reduced motion и прежнего режима слабых устройств.
- bot.py и настройка кнопки «Открыть» не изменены.

## Сохранения

Переписывать или заменять базу данных не нужно. Старые business_id (coffee, taxi и т.д.) сохраняются вместе с уровнями, улучшениями и привязками автопарков. Дополнительные экземпляры получают ключ вида taxi~UUID. Тип используется только для поиска параметров в каталоге; любые действия в SQL ограничены полным ключом экземпляра и авторизованным user_id.

При установке оставьте текущие DB_PATH и Railway Volume. ZIP не содержит базу игроков или .env. Применяющий скрипт их не копирует и не меняет. Перед деплоем сохраните актуальную резервную копию рабочей базы штатной функцией администратора. Возвращать старый код после покупки новых экземпляров нельзя без учёта новых ключей: старые версии не умеют учитывать их в доходе.

## Применение в PowerShell

Скачайте ZIP в папку «Загрузки». Выполните команды ниже. Введите путь именно к своему существующему git-проекту Corporation. Скрипт сохранит копии заменяемых исходников рядом с проектом. Он обновляет только перечисленные файлы, не затрагивая bot.py и настройки Railway.

```powershell
$projectPath = Read-Host 'Полный путь к папке corporation-game'
$archive = Join-Path $env:USERPROFILE 'Downloads\Corporation_v28_MULTI_BUSINESS_SMOOTH.zip'
$stage = Join-Path $env:TEMP ('Corporation_v28_' + [guid]::NewGuid().ToString('N'))
Expand-Archive -LiteralPath $archive -DestinationPath $stage
& powershell.exe -NoProfile -ExecutionPolicy Bypass -File (Join-Path $stage 'APPLY_UPDATE_V28.ps1') -ProjectPath $projectPath
if ($LASTEXITCODE -ne 0) { throw 'Обновление не применено' }
Set-Location -LiteralPath $projectPath
git diff --stat
git add -- app.py web/app.js web/index.html web/v20.js web/premium_v24.js web/premium_v25.js web/instances_v28.js web/instances_v28.css tests/test_instances_v28.py tests/test_instances_v28.cjs README_V28_RU.md
git commit -m "v28: independent business instances and smooth UI"
if ($LASTEXITCODE -ne 0) { throw 'Проверь результат git commit перед push' }
git push
```

После успешного деплоя закройте Mini App полностью и откройте заново. Ссылки JS/CSS имеют новую версию кэша v280. Дополнительных переменных окружения и изменений команды запуска не требуется. Как и раньше, SQLite-сервис запускается с одним worker.

## Проверки

Пройдены 31 прежний Python-тест и 6 новых API/SQLite-тестов:
- 5 независимых кофеен; улучшение и продажа только выбранного экземпляра;
- по 3 Такси и Логистики: разные автопарки, гаражи и таймеры;
- повторная инициализация сохраняет старые и новые записи;
- доход и капитализация учитывают экземпляры; начисление за час проверено;
- чужой экземпляр недоступен для изменений;
- одновременные покупки создают разные записи с правильным списанием.

Браузерный тест Chromium: ширины 320/390/768/1280; по три последовательных покупки машины в Такси и Логистике; неизменность DOM-узлов и прокрутки; отмена; ползунок покупки и продажи; сумма; запрет дробного количества; отсутствие POST при перемещении ползунка и отмене; один POST после подтверждения; скрытие панели на остальных вкладках. Ошибок JavaScript в проверенных сценариях нет.

Тесты выполнялись на временной базе. Реальная база Railway и Telegram WebView на физических телефонах недоступны для проверки в этой среде.

Для повторного запуска:
```powershell
python -m unittest discover -s tests -p 'test_*.py' -v
```
Браузерный тест: tests/test_instances_v28.cjs. Нужны Playwright и Chromium; пути можно задать через PLAYWRIGHT_PATH и CHROMIUM_PATH. Python запускается командой python3 (на Windows при необходимости замените её в тесте на python).
